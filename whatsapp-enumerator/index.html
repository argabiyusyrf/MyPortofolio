01

The problem & the decision

Context

Verifying whether a set of Indonesian phone numbers is registered on WhatsApp usually means slow, manual lookups — and doing it at scale invites getting rate-limited or banned. The tool needed to be fast, polite, and able to survive interruptions.

So I built a queue-based CLI: it expands partial numbers, checks registration on your own session, respects rate limits, writes checkpoints, and resumes where it stopped. Nothing burns between runs.

02

Core architecture

01 — Session

Headless WhatsApp Web session

Session management via whatsapp-web.js, authenticated once and reused — your own session, your own safety.

02 — Queue

Async queue with rate limiting

Requests run through an asynchronous queue with configurable batch delay — throughput you control, not chaos.

03 — Recovery

State persistence & resume

Progress checkpoints written continuously. Interrupt the process, rerun it, and it picks up exactly where it stopped.

04 — Output

Clean terminal & CSV export

A tidy dashboard in the terminal plus formatted CSV telemetry — data you can hand to any spreadsheet.
