01

The problem & the decision

Context

Ordering systems usually grow into a tangle: a menu here, a cart there, a kitchen view somewhere else — each with its own conventions. Foodcraft exists to prove the opposite: one clean router, one schema, and a visible state machine for every order.

Every order travels a defined path — queued, preparing, out for delivery, delivered. The backend never guesses; it only moves forward, and the client updates without a single heavy library.

02

Core architecture

01 — Routing

Custom regex-based HTTP router

A single routing table maps every URL to a controller. Regex patterns keep the routes readable while staying powerful enough for nested resources.

02 — Views

Modular controllers & templates

Controllers handle logic; template views handle presentation. A tiny rendering engine keeps them separate and clean to read.

03 — Data

Relational schema for orders

Dynamic menu options, carts, orders, and deliveries modeled as normalized relations — the state machine lives in the data, not in scattered flags.

04 — Frontend

Optimized DOM updates

Order state changes update the DOM with zero heavy libraries — plain, deliberate JavaScript that keeps the interaction snappy.
