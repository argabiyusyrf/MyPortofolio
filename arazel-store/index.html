01

The problem & the decision

Context

Every e-commerce template I found was either a heavyweight framework (Laravel, Symfony) with hundreds of dependencies, or a drag-and-drop builder that hides everything that matters. Neither fit the constraint that matters most here: a store that loads fast on a $6 VPS and stays maintainable without a dependency graph the size of a novel.

So I wrote the core myself. A front controller, a tiny router, a PDO layer, a session engine — nothing that isn't strictly needed. The result is a store with no cold starts, no artisan commands, and no mystery between the request and the response.

02

Core architecture

01 — Routing

Hand-rolled lightweight MVC

A single front controller dispatches every request through modular controllers and views. No framework magic — every layer is plain PHP you can read in one sitting.

02 — Data

PDO-based MySQL layer

Relational schema for users, products, carts, and orders. Parameterized queries only — no string-built SQL, no injection surface.

03 — Sessions

Custom session auth

Session-based authentication with verified state on every request. Passwords hashed properly, cart state bound to the session.

04 — Serving

Nginx server blocks

Fast static asset serving, gzip, cache headers, and clean reverse proxy rules — the store never waits on PHP for a CSS file.
